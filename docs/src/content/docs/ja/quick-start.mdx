**heal はコードベースの劣化をエージェントの仕事に変えます。** コミットのたびに複雑度・Hotspot・重複を再計測し、出てきた TODO リストを Claude に渡します。Claude は修正を提案し、承認されたものを 1 件ずつコミットしていきます。人間はポーリング役から降りられます。このページではそのループを最後まで、5 分ほどで立ち上げます。

## 必要環境

始める前に揃えておくもの:

- macOS または Linux
- 評価対象の git リポジトリ
- (任意)[Claude Code](https://claude.com/code) — heal プラグインの `/heal:setup`・`/heal:refactor`・`/heal:docs`・`/heal:tests` スキルを使う場合

## 2. リポジトリをブートストラップ

`.heal/` の作成と git フックの設置を、このコマンド 1 つでまとめて行います。

```sh
heal init
```

`.heal/`(設定と Calibration)を作り、コミットのたびに次の Critical / High を表示する post-commit フックをインストールします。何度実行しても安全で、`--force` を付けない限り既存の設定と Calibration はそのまま残ります。何が済んでいて何が残っているかは `heal doctor` で確認できます。

## 3. プラグインを入れて `/heal:setup` を実行する

スキルは Claude Code プラグインとして配布しています。Claude Code で次を実行します。

```
/plugin marketplace add kechol/heal
/plugin install heal@heal
```

続けてセットアップ用のスキルを実行します。任意ですが、最初は実行をおすすめします。

```
/heal:setup
```

`heal doctor` の結果から始めるので、足りないことだけを行います。Strict / Default / Lenient のどれにするかを聞いて `.heal/config.toml` を更新し、オプションの Test / Docs / Semantic ファミリを有効にするか確認して、必要なもの(doc pairs、カバレッジのリポータ、concept の一覧)を用意します。再 calibrate はあなたが同意したときだけです。いつ再実行してもかまいません。セットアップ済みのプロジェクトなら、そろっていると報告するだけで終わります。

## 4. TODO リストを見る

有効 Drain Tier と Severity でまとまり、同一ファミリ内では Hotspot スコア降順になった項目の一覧です。

```sh
heal status
```

ファイル単位の TODO リストを Tier、Severity、スコア順で表示します。フィルタや JSON 出力は [CLI › heal status](/heal/ja/cli/#heal-status) を参照。

## 5. Claude と Finding を片付ける

どのスキルも、heal が見つけたものを読んで変更を提案し、あなたが承認したものだけを適用します。1 提案につき 1 コミットで、コミットの前にテストを実行します。push や pull request の作成はしません。

```
/heal:refactor          # コードの Finding をシステムとして読み、構造的なものも含めてリファクタを提案する
/heal:refactor plan     # 提案だけ。適用は後で
/heal:docs              # [features.docs]: Diátaxis の視点でドキュメントを直す・書き直す・移す・分ける
/heal:docs scaffold     # [features.docs]: docs がまだ無いプロジェクトで、コードベースからドキュメントツリーを作る
/heal:tests             # [features.test]: テストピラミッドの視点でテストを書く・合わせる・skip を戻す・消す
```

スキルの詳細は [Code › スキル](/heal/ja/code/skills/)、[Docs › スキル](/heal/ja/docs/skills/)、[Test › スキル](/heal/ja/test/skills/) を参照。
